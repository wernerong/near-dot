# Near Dot 1.0.3

Recover a saved message when ChatGPT accepts the relay event but no reply returns, including event-triggered runs that arrive without message data.

## Changes

- Let the existing `read_test_message` tool retrieve up to ten unanswered submitted messages when `message_id` is omitted or set to `pending`. It returns the original message IDs, excludes unsent drafts and answered history, and respects the local access deadline.
- Add **Request reply again** after three minutes without a reply. This creates a fresh notification for the same saved message. Failed transport retries keep their event ID, while explicit reminders receive a new event ID. Replies still occupy one immutable slot per message.
- Persist the last delivery attempt so restarting the app does not bypass the reminder delay. Upgrade the existing mailbox in place without replacing its messages or replies.
- Label local transport readiness **Relay connected**. Acknowledged delivery and an actual dot reply remain separate states.
- Correct the read tool's description to use `data.message_id`, and include missing-event-data recovery in setup instructions.

## Existing live connections

After installing, rescan the existing Near Dot MCP plugin so ChatGPT discovers its updated tool description. Add this instruction to the existing dot subscription:

> When a Near Dot event has no message ID or event data, call read_test_message with message_id set to pending. Answer each returned message through reply_to_test_message using its returned message_id. Continue while has_more is true. Do not guess an ID or include unrelated conversation history.

This uses the same authorized private connection and saved relay mailbox. It does not synchronize ChatGPT conversation history. The recovery depends on the dot invoking the read and reply tools; webhook acknowledgement alone does not prove processing.

## Validation and distribution

Synthetic regressions cover missing event data, bounded pending batches, unsent-draft exclusion, expired access, restart and legacy-mailbox migration, retry cooldown, failed reminders, terminal rejection, late replies and duplicate replies. Browser checks cover recovery with the original message ID and disabled recovery while disconnected. Exact-source native CI and protected release drills must pass before publication.

The reported incident had a healthy tunnel, an active subscription and one acknowledged unanswered message. Its outbound event shape matches the current official MCP Events contract. The reason ChatGPT reported missing event data has not been established; this release repairs the local inability to recover that condition.

Windows installers retain the existing distribution model without Authenticode signing. Mac bundles are ad-hoc sealed without Developer ID signing or notarization. Mandatory updater signatures, checksums and GitHub provenance accompany the release. Keep OS protections enabled.
