# Near Dot 1.0.2

Repair Windows settings and artwork that appeared reset after an update or a different launch path, and give chat messages more room.

## Changes

- Extend the companion size range from 120–240 to 48–240 logical pixels while preserving saved sizes and the default size.
- Remove the caption under the desktop icon and its extra window space. Click or keyboard-activate the image to open chat; settings and reply actions remain available.
- Collapse connection controls into a keyboard-accessible Connection options row instead of a tall stack below the composer. Connection status stays visible in the header.
- Start the composer at one line, expand it as you type up to four lines, and return it to its compact height after sending. Reduce header and notice spacing while retaining message scrolling and the existing send keyboard shortcuts.
- Store Windows preferences and artwork in the user's `.near-dot` directory outside AppData. Packaged-host and ordinary Windows launches now select the same settings store.
- Import the launching profile's existing preferences and image once using atomic copies. Keep originals, preserve corrupt/future schemas, keep existing choices in the new store, and resume an interrupted migration without replacing files already copied.
- Keep avatar imports, resets and preserved image backups in that same active settings directory. Completed migration does not reintroduce an image after an intentional reset.
- Report preference read failures instead of silently treating an unreadable file as a fresh installation.
- Strengthen the Windows upgrade drill to launch the actual upgraded app three times and inspect its migrated settings and image, including retention after reinstall and uninstall.

The incident was reproduced as two different filesystem views: a packaged-host profile retained the configured preferences and image, while an unpackaged process read defaults with no image. Windows documents this behavior as [AppData virtualization](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes). The original files were not deleted.

## Install or update

Use `NearDot-1.0.2-windows-x86_64.exe` or an eligible signed update. Existing Windows preferences and artwork migrate from the launching profile's former app-config directory to `%USERPROFILE%\.near-dot`. If older launch contexts already have conflicting profiles, first launch from the one containing the wanted settings or recover those files locally before migration. Existing new-store files always win. Near Dot does not scan other applications' private package directories.

Mac uses its existing storage location and public launcher. Windows chat setup, its protected connection directory, runtime key and saved relay exchanges are unchanged. This release adds no account permissions, shared memory, full ChatGPT history or new dot route.

The existing OS distribution model continues: Windows installers are not Authenticode signed; Mac bundles are ad-hoc sealed without Developer ID signing or notarization. Keep OS protections enabled. Package/feed updater signatures remain mandatory; checksums and GitHub provenance accompany the release.

## Validation and limits

Regression tests cover launcher-independent Windows storage selection, byte-preserving migration, future-schema preservation, restart without reimport, interrupted migration and unreadable legacy files. Exact-source CI and the protected release workflow must pass before publication. The Windows release drill uses an actual upgrade from v1.0.1 and repeated candidate launches; earlier v1.0.1 checks alone do not establish this repair.

The live relay and private account authorization are unchanged. Full physical accessibility, power-loss recovery and every managed Windows profile configuration remain unverified.
