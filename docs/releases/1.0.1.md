# Near Dot 1.0.1

Windows startup repair and desktop chat update for the v1.0.0 launcher.

## Changes

- Initialize Rust application and chat state before creating desktop webviews, preventing startup crashes caused by early window events or UI requests.
- Open the shared chat panel when the Windows companion is clicked, with saved exchanges and real incoming reply notifications.
- Bundle checksum-pinned Python 3.13.12 and the official tunnel client v0.0.15 so Windows connection setup needs no system Python, terminal commands or separate client download.
- Add guided per-user connection setup through official OpenAI settings and a native credential prompt. Windows and Mac connections remain separate.
- Keep the authorized Windows connection, local exchanges, preferences and artwork outside installer resources so upgrades preserve them. Reconnect automatically after launch; disconnect pauses reconnecting and forget removes local credentials while retaining exchanges.
- Keep background helpers hidden and stop their process trees when Near Dot exits or crashes. Close an unfinished native setup prompt when its parent exits.

## Install or update

Download `NearDot-1.0.1-windows-x86_64.exe` for Windows 10/11 x64. Existing installations can use a verified update when the signed channel offers it. Preferences and imported images remain local. Apple Silicon and Intel Mac installers retain the public launcher; the separately configured private Mac chat build is not enabled in those public packages.

Windows live messaging requires each user's own eligible OpenAI workspace, private tunnel, restricted runtime key, connected MCP plugin and dot event subscription. Choose **Chat → Connect my dot**. Enter secrets only in the native prompt. The installer prepares the local runtime but cannot grant account permissions. Browser sign-in alone does not complete authorization. No account credentials, private destinations or user artwork are bundled.

The existing OS distribution model continues: Windows installers are not Authenticode signed; Mac apps are ad-hoc sealed without Developer ID signing or notarization. OS policy can warn or block installation. Keep OS protections enabled. Tauri package and feed signatures remain mandatory; checksums and GitHub provenance accompany release assets.

## Validation and limits

The preceding Windows review build passed three-platform CI and repeated actual Windows launches. One authorized Windows setup completed an automatic dot reply and native notification test. Two subsequent Windows relaunches retained the chosen image and reconnected automatically, and a fresh message received the exact requested reply across a restart. These observations establish that tested setup, not universal account eligibility or uninterrupted delivery.

The v1.0.1 release workflow additionally requires exact-commit validation and installer/update/recovery drills before producing its draft. The workflow logs and asset review establish the final candidate's results; earlier tests do not substitute for those checks.

One earlier Windows app instance displayed default artwork and first-run settings while the saved files remained intact. Relaunch restored them, but the failing startup condition was not reproduced or diagnosed. This release does not claim a specific fix for that incident.

Only Near Dot relay exchanges appear in its history. Full ChatGPT conversation/history or shared-memory synchronization, voice, global dot activity and automatic avatar sync remain unavailable. Delivered webhooks can be processed asynchronously; service outages or account changes can delay replies. Physical accessibility, power-loss installation recovery and the full login/monitor/network matrix remain unverified.
